# 数据与资讯管线方案

## 1. 目标

数据与资讯管线负责为回测、模拟盘、风险卡、市场解释和知识库提供可追溯的数据。核心原则是：数据可以缺，但不能编；数据异常必须显式进入状态。

## 2. 数据源分层

P0免费数据源：

- AKShare：A股、指数、ETF、基金、行业相关数据。
- efinance：股票、基金、债券、期货行情补充。
- qstock：个人量化投研数据、可视化和回测辅助。
- BaoStock：A股日线、复权、指数、基础财务指标补充，适合做免费源交叉校验。
- 巨潮资讯：上市公司公告、定期报告、临时公告、基金公告，优先存标题、摘要、链接、发布时间和关联标的。
- 交易所公开信息：上交所、深交所、北交所公告、监管函、停复牌、交易异常、指数样本等。
- 监管公开信息：证监会、基金业协会、证券业协会、地方证监局风险提示和规则更新。

P1稳定数据源：

- Tushare Pro：股票、指数、基金、ETF、公告、新闻快讯等。
- 低成本资讯API：用于补充新闻快讯、宏观日历、行业事件，但必须保留原始来源和授权口径。

P2扩展：

- OpenBB式统一数据适配。
- Choice、Wind、同花顺iFinD、财联社、券商研报/数据接口。
- 交易所或指数公司授权数据。
- 付费源只在验证真实付费和留存后接入，避免MVP成本失控。

P3自建数据资产：

- 用户创建的策略、回测报告、模拟盘表现、风控事件。
- 用户提问、追问、收藏、反馈、取消订阅原因。
- 策略失败案例库、过拟合样本库、风险事件库。
- 本地alpha启发策略、因子族标签、相似策略表现、策略质量评分。

## 2.2 数据授权与版权规则

- 免费源可以用于MVP验证，但每个接口必须记录来源、抓取时间、数据时间、字段口径和可用性。
- 对网页、公告、新闻、研报，只默认入库标题、摘要、链接、发布时间、来源、关联标的和主题标签。
- 长文全文、研报全文、新闻全文、图片和PDF下载必须先确认robots、服务条款、版权和商业使用边界。
- 对用户可见内容必须展示“数据来源”和“最后更新时间”，不能让AI把来源混成自己的判断。
- 商业数据源不能和免费抓取数据混用后隐藏来源；若授权限制不允许二次展示，只能用于内部计算或摘要。
- 多源冲突时进入 `conflict` 状态：展示“数据源冲突”，不让AI自行选择对用户输出确定结论。

## 3. 数据适配层

统一接口：

- `MarketDataProvider`：K线、实时/延迟行情、指数、行业。
- `FundDataProvider`：基金/ETF净值、规模、跟踪指数。
- `NewsProvider`：资讯、公告、宏观、行业新闻。
- `CalendarProvider`：交易日历、休市日、下一个交易日。
- `AnnouncementProvider`：巨潮、上交所、深交所、北交所公告。
- `FinancialReportProvider`：利润表、资产负债表、现金流量表、财务指标、业绩预告、分红。
- `IndustryProvider`：申万/中信行业、概念板块、行业成分、行业ETF映射。
- `ResearchProvider`：研报摘要、新闻摘要、事件标签；P0只处理可公开抓取和可引用内容。
- `RegulatoryProvider`：证监会、交易所、协会、地方证监局规则和风险提示。
- `AlternativeDataProvider`：后置扩展，用于搜索热度、舆情热度、互动平台问答等非结构化信号，V1仅做研究不展示为确定结论。

每个provider必须返回：

- 数据本体。
- 来源。
- 抓取时间。
- 数据时间。
- 数据质量状态。
- 授权/展示状态：`public_linkable`、`internal_only`、`licensed_displayable`、`unknown_rights`。
- 原始ID或原始URL，便于追溯和审计。

## 3.1 标准化数据对象

### AssetProfile

- 标的代码、名称、市场、类型、上市日期、行业、概念、指数/ETF映射、状态。
- 个股只用于背景解释和风险标签，不作为推荐入口。

### FinancialSnapshot

- 报告期、营业收入、归母净利润、扣非净利润、毛利率、净利率、ROE、资产负债率、经营现金流、同比/环比。
- 每个字段必须有财报来源和报告期，不允许AI根据新闻推断财报数字。

### AnnouncementItem

- 标题、公告类型、发布时间、来源、链接、关联标的、摘要、风险标签。
- 公告摘要必须标注“机器摘要”，并保留原文链接。

### IndustrySnapshot

- 行业名称、分类体系、成分股、行业ETF、近5/20/60日表现、成交额变化、波动率、回撤分位、热度标签。

### NewsEvent

- 标题、来源、发布时间、事件时间、摘要、主题、关联行业/ETF/个股、可信度、版权状态。

## 4. 数据质量状态

- `ok`：正常。
- `delayed`：延迟。
- `partial`：部分缺失。
- `unavailable`：不可用。
- `conflict`：多源数据冲突。
- `stale`：数据过旧。

处理规则：

- `ok`：正常计算。
- `delayed`：展示延迟提示。
- `partial`：只计算可用部分，并展示缺失字段。
- `unavailable`：不生成结论。
- `conflict`：优先使用权威源，记录冲突。
- `stale`：禁止用于当日模拟更新。

## 5. 行情管线

盘后任务：

1. 获取交易日历。
2. 拉取A股/ETF日线。
3. 拉取指数和行业数据。
4. 拉取基金/ETF基础数据。
5. 校验字段、日期、缺口、复权。
6. 写入数据库。
7. 触发模拟盘更新。
8. 刷新榜单。

关键校验：

- 日期是否为交易日。
- OHLC是否合法。
- 成交量/成交额是否异常。
- 是否停牌。
- 是否触及涨跌停。
- 前复权/后复权口径是否一致。

## 6. 资讯管线

V1只做辅助解释，不做实时交易信号。

资讯类型：

- 市场新闻。
- 行业新闻。
- 基金/ETF公告。
- 公司公告，个股仅作背景。
- 宏观事件。
- 监管风险提示。
- 财报、业绩预告、分红、减持、回购、重大合同、诉讼、问询函。
- 研报摘要：V1只做公开可引用摘要，不抓取和展示受版权保护全文。

处理流程：

```mermaid
flowchart LR
  A["抓取资讯"] --> B["去重"]
  B --> C["来源和时间校验"]
  C --> D["分类"]
  D --> E["摘要"]
  E --> F["合规过滤"]
  F --> G["关联行业/ETF/策略"]
```

资讯输出不能写成：

- “因该新闻建议买入”。
- “该消息利好，马上上涨”。

允许写成：

- “该新闻可能影响行业情绪，需结合量化指标观察”。
- “该事件是策略模拟表现的背景之一，不构成投资建议”。

## 6.1 公告、财报、监管抓取策略

公告抓取：

1. 每日盘后抓取巨潮、上交所、深交所、北交所公告列表。
2. 按公告类型打标签：定期报告、业绩预告、分红、减持、回购、重组、诉讼、问询函、监管函、停复牌。
3. 建立标的关联：股票代码、基金代码、行业、ETF映射。
4. 对可展示内容生成短摘要，不展示长篇全文。
5. 对高风险公告进入 `risk_event_logs`，供风险卡、策略复盘和AI问答引用。

财报处理：

1. 优先使用可结构化来源抓取三大表和关键指标。
2. 对同一报告期做多源校验；冲突时标记 `conflict`。
3. 只把已确认字段交给AI解释，禁止AI补完缺失财务数字。
4. 输出时必须显示报告期、来源、发布时间和是否为最新定报。

监管信息：

1. 采集证监会、交易所、基金业协会、证券业协会公开信息。
2. 将监管规则、风险提示、处罚案例进入知识库和合规词库。
3. 对“AI炒股、荐股软件、虚拟盘、量化交易包装、私域带单”等主题建立长期风险专题。
4. 每月复核合规文案，重大监管更新需人工确认后上线。

## 7. 市场解释数据

市场解释依赖：

- 指数涨跌。
- 行业涨跌。
- 成交额。
- 波动率。
- ETF热度。
- 新闻摘要。

AI只能基于已计算字段生成解释，不得自行编造原因。

## 8. 数据存储建议

表：

- `market_bars`：K线。
- `asset_metadata`：标的基础信息。
- `trading_calendar`：交易日历。
- `data_quality_logs`：数据质量日志。
- `news_items`：资讯原文和摘要。
- `market_snapshots`：市场解释快照。
- `asset_profiles`：标的画像、行业、概念、ETF映射。
- `financial_snapshots`：财报和关键财务指标。
- `announcement_items`：公告、摘要、来源、风险标签。
- `industry_snapshots`：行业温度、成分、ETF映射。
- `regulatory_items`：监管规则、风险提示、处罚案例。
- `source_registry`：数据源、授权口径、限流、可展示范围。
- `risk_event_logs`：公告、新闻、行情异常生成的风险事件。
- `data_conflict_logs`：多源冲突记录和处理状态。

## 8.1 数据透明展示

用户可见页面必须提供：

- 数据来源名称。
- 最后更新时间。
- 数据质量状态。
- 是否延迟。
- 关键指标计算口径。
- 如果是机器摘要，必须标注“AI摘要/机器摘要”。
- 如果数据不足，展示“暂无足够依据”，不能输出确定结论。

## 9. 降级策略

- 免费源A失败：尝试免费源B。
- 多源失败：展示数据不可用。
- 资讯失败：只展示量化指标，不生成新闻归因。
- 交易日历异常：暂停模拟盘更新。
- 单标的数据异常：该策略标记为 `data_insufficient`。
